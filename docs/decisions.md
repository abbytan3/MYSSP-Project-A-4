- 2026-11-19 (T11, Abby): Output file stores `top` as a float32 scalar, `shape` as int32 (height, width) and `flag` as a uint8 1-D array. Why: the smallest types that hold the values; float32 matches what the detectors produce. Chosen over float64 or int64, which only make files bigger.
- 2026-11-19 (T11, Abby): `flag` is the 0.5 mask flattened row by row (C order) and packed with `np.packbits` (default big bit order); on reading, `np.unpackbits(flag)[:h*w].reshape(h, w)` restores it, so the padding bits at the end are dropped. Why: the simplest packing and the only one that needs just `shape` to undo. Chosen over saving the mask unpacked or as region lists, which are larger or already depend on scoring choices.
- 2026-11-19 (T11, Abby): The heat map is converted to float32 before anything is computed, so `top` and `flag` always agree, and a pixel is flagged when value >= 0.5 (inclusive). Saving refuses NaN, values outside 0 to 1, and page IDs that are not `page_NNNN`. Why: a NaN would silently count as "not flagged", and real file names must never reach the output. Limitation: a float64 value just under 0.5 that rounds to exactly 0.5 in float32 is flagged.
- 2026-11-19 (T11, Abby): `run_info.json` and `run_log.csv` are written inside each output folder, `out/<detector>/<size>/`, next to the .npz files (run_log columns: page_id, size, seconds, max_value, status). Why: one folder per detector and size holds everything for that run, so a run can be checked or rerun on its own. Chosen over one file per detector, which would mix the two sizes.
- 2026-11-19 (T11, Abby): DAF boxes become a heat map by rounding box edges outwards (floor x1,y1; ceil x2,y2), treating the end as exclusive, clipping to the page, filling with the box score and keeping the maximum on overlaps (helper `boxes_to_heatmap` in `shared/output_format.py`). Why: PLAN.md section 3 says fill each box with its score and keep the maximum; outward rounding never shrinks a box. Chosen over rounding to nearest, which could cut a box edge. Limitation: boxes can grow by up to 1 pixel per side.
- 2026-11-19 (T20, Abby): Week 7 ablation part 1 rescores the safe per_page.csv with rule A (`flagged_any`) and "edit found" (the file's `detected` column, which equals recall > 0 on every tampered row). Clean pages for each cell are the `untouched` rows of the same detector, size, format and set. Chosen over rule B for now, because rule B needs T11's shared scoring functions. Limitation: false-region counts cannot be recomputed (heat maps not kept), so location precision and F1 are left out.
- 2026-11-19 (T20, Abby): Ablation 95% ranges use 1,000 bootstrap resamples (seed 42) of source pages, keyed by set and page ID, taking every row of a drawn page together, because the safe files have no document ID. Chosen over resampling rows, which would split a page from itself. Limitation: it is assumed, not checked, that one page ID is one source document across versions and formats.
- 2026-11-19 (T20, Abby): The ablation reads the ADCD-Net, DTD, DAF AnyText and DAF DiffSTE per_page.csv files and excludes the DAF SRNet file, by Abby's decision, to match the main study's 2 DAF weights (PLAN.md section 3: "Released AnyText and DiffSTE weights (team Drive); SRNet weight not used"). Chosen over including it, although Week 7 had it. DAF's extra `default` size is kept and labelled as is. Limitation: Week 7 figures that used the SRNet weight can't be reproduced from this table.
- 2026-11-19 (T09, Abby): Each document is counted once as an untouched original, and the set1 copy of its authentic page is used. Why: set1 and set2 hold the same authentic image for every document (same sha256 in assignment.csv). Chosen over keeping both copies, which would score the same image twice.
- 2026-11-19 (T09, Abby): The sample has 644 untouched originals (589 documents behind the sampled edits + 55 stage 2 originals whose documents have no sampled edit), against PLAN.md's "about 655". The count is whatever the plan's rule gives; AI (506) and handcrafted (500, 333/95/72) match exactly. Chosen over adding pages to reach 655, which no rule in the plan supports. Limitation: the originals are 11 fewer than the plan's estimate.
- 2026-11-19 (T09, Abby): 6 real stage 2 authentic pages are not in the stage 1 split, so their labels and document IDs are read from the Week 6 stage 2 split (`31_filtered`) and used only for those 6. Why: PLAN.md section 5 compares people and detectors on all 500 real stage 2 pages, and these 6 documents exist only there. Chosen over leaving them out (174 of 180 authentic pages). - 2026-11-19 (T09, Abby): Randomness and IDs: seed 42; handcrafted fill is drawn with `random.Random(42)` from the sorted pool after all 160 stage 2 pages are included; the final list is shuffled with the same seed before numbering, so page_0001 and doc_0001 order reveals neither group nor file order. Reviewer 3's latest decision per page is the one with the latest timestamp (ties: later line). Chosen over numbering in file order, which would leak the group.
- 2026-11-19 (T09, Abby): `meta/sample.csv` has two columns beyond PLAN.md's list: `doc_id` (anonymous, doc_0001…) and `ext` (file extension). Why: section 4 resamples documents with their pages together for the 95% ranges, and the jobs must find `pages/<page_id>.<ext>`. Chosen over leaving them out, which would force the scoring script to read the private sample_map.csv.
- 2026-11-19 (T11, Abby): The scoring script refuses a run whose `run_info.json` lacks any of: detector, weights, size, tile_size (may be null), versions, seconds_per_page, seed; the error names every missing field. Why: PLAN.md section 3 and AGENTS.md require each run's settings to be saved next to its results, and a missing field found at scoring time is too late to rerun cheaply. Chosen over scoring whatever file is there.
- 2026-11-19 (T11, Abby): Regions are 8-connected groups of flagged pixels (scipy `ndimage.label`). An edit is found if any region has a pixel inside its box; a false region is a region with no pixel inside any box on its page; one region touching two boxes finds both. Box edges are rounded outwards, end exclusive, and clipped to the page (same rule as the DAF box fill). Limitation: a very large region that covers a box counts as found, with no penalty for its size.
- 2026-11-19 (T11, Abby): Rule B splits documents (seed 42 permutation of the anonymous document IDs, pages of one document together) into two halves; the cut-off for each half is chosen on the other half and the predictions are pooled. Candidates are the distinct top scores of the training half, a page is tampered when top >= cut-off, the cut-off maximising F1 wins, ties go to the lowest. Edited pages (AI and handcrafted together) are the positives. The split depends only on sample.csv, so it is the same for every detector and size. Chosen over a fixed cut-off or one chosen on all pages, which would let test pages pick their own cut-off.
- 2026-11-19 (T11, Abby): 95% ranges are the 2.5th and 97.5th percentiles of 1,000 bootstrap resamples of documents (seed 42), with the same draws for every size and subset so differences are paired; a difference is "clear" only if its range excludes 0. The rule B predictions come from one cross-fit and are not redone inside each resample. Chosen over re-fitting the cut-off per resample, which is slower and needs more code. Limitation: the ranges do not include the uncertainty from choosing the cut-off.
- 2026-11-19 (T11, Abby): Breakdown rows score the edited pages of the subgroup (AI vs handcrafted, each editor, each method) against all untouched pages, using the same rule B cut-offs; the capture-condition rows use only edited and untouched pages with that condition. Pages with no output file are left out of every metric and listed (anonymous IDs) in score_info.json, never filled in. The stage 2 human-grade breakdown is not in this script. Limitation: untouched pages are shared between subgroup rows, so those rows are not independent.
- 2026-11-19 (T20, Abby): Ablation results are reported per set. The 178 images per format (untouched, generation, splicing, copy-move on the 49 shared source pages) appear identically under both AnyText and DiffSTE, so any pooled result must count them once, grouped by source page. Chosen over pooling the two sets row by row, which would double-count them. Limitation: AnyText and DiffSTE cells for these four versions are not independent evidence.
