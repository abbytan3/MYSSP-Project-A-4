- 2026-11-19 (T11, Abby): Output file stores `top` as a float32 scalar, `shape` as int32 (height, width) and `flag` as a uint8 1-D array. Why: the smallest types that hold the values; float32 matches what the detectors produce. Chosen over float64 or int64, which only make files bigger.
- 2026-11-19 (T11, Abby): `flag` is the 0.5 mask flattened row by row (C order) and packed with `np.packbits` (default big bit order); on reading, `np.unpackbits(flag)[:h*w].reshape(h, w)` restores it, so the padding bits at the end are dropped. Why: the simplest packing and the only one that needs just `shape` to undo. Chosen over saving the mask unpacked or as region lists, which are larger or already depend on scoring choices.
- 2026-11-19 (T11, Abby): The heat map is converted to float32 before anything is computed, so `top` and `flag` always agree, and a pixel is flagged when value >= 0.5 (inclusive). Saving refuses NaN, values outside 0 to 1, and page IDs that are not `page_NNNN`. Why: a NaN would silently count as "not flagged", and real file names must never reach the output. Limitation: a float64 value just under 0.5 that rounds to exactly 0.5 in float32 is flagged.
- 2026-11-19 (T11, Abby): `run_info.json` and `run_log.csv` are written inside each output folder, `out/<detector>/<size>/`, next to the .npz files (run_log columns: page_id, size, seconds, max_value, status). Why: one folder per detector and size holds everything for that run, so a run can be checked or rerun on its own. Chosen over one file per detector, which would mix the two sizes.
- 2026-11-19 (T11, Abby): DAF boxes become a heat map by rounding box edges outwards (floor x1,y1; ceil x2,y2), treating the end as exclusive, clipping to the page, filling with the box score and keeping the maximum on overlaps (helper `boxes_to_heatmap` in `shared/output_format.py`). Why: PLAN.md section 3 says fill each box with its score and keep the maximum; outward rounding never shrinks a box. Chosen over rounding to nearest, which could cut a box edge. Limitation: boxes can grow by up to 1 pixel per side.
- 2026-11-19 (T20, Abby): The Week 7 ablation rescores the safe per_page.csv files with rule A (`flagged_any`), rule B and AUC (all from `shared/score.py`, commit 2abe755) and "edit found" (the file's `detected` column, which equals recall > 0 on every tampered row). Clean pages for each cell are the `untouched` rows of the same detector, weights, size, format and set. Limitation: false-region counts cannot be recomputed (heat maps not kept), so location precision and F1 are left out. `shared/score.py` has not changed since 2abe755, and the T11 real-page check of it has passed (commit f0a4dc8), so the ablation needs no rerun.

- 2026-11-19 (T11, Abby): The scoring script refuses a run whose `run_info.json` lacks any of: detector, weights, size, tile_size (may be null), versions, seconds_per_page, seed; the error names every missing field. - 2026-11-19 (T11, Abby): Regions are 8-connected groups of flagged pixels (scipy `ndimage.label`). An edit is found if any region has a pixel inside its box; a false region is a region with no pixel inside any box on its page; one region touching two boxes finds both. Box edges are rounded outwards, end exclusive, and clipped to the page (same rule as the DAF box fill). Limitation: a very large region that covers a box counts as found, with no penalty for its size.
- 2026-11-19 (T11, Abby): Rule B splits documents (seed 42 permutation of the anonymous document IDs, pages of one document together) into two halves; the cut-off for each half is chosen on the other half and the predictions are pooled. Candidates are the distinct top scores of the training half, a page is tampered when top >= cut-off, the cut-off maximising F1 wins, ties go to the lowest. Edited pages (AI and handcrafted together) are the positives. The split depends only on sample.csv, so it is the same for every detector and size. Chosen over a fixed cut-off or one chosen on all pages, which would let test pages pick their own cut-off.
- 2026-11-19 (T11, Abby): 95% ranges are the 2.5th and 97.5th percentiles of 1,000 bootstrap resamples of documents (seed 42), with the same draws for every size and subset so differences are paired; a difference is "clear" only if its range excludes 0. The rule B predictions come from one cross-fit and are not redone inside each resample. Chosen over re-fitting the cut-off per resample, which is slower and needs more code. Limitation: the ranges do not include the uncertainty from choosing the cut-off.
- 2026-11-19 (T11, Abby): Breakdown rows score the edited pages of the subgroup (AI vs handcrafted, each editor, each method) against all untouched pages, using the same rule B cut-offs; the capture-condition rows use only edited and untouched pages with that condition. Pages with no output file are left out of every metric and listed (anonymous IDs) in score_info.json, never filled in. The stage 2 human-grade breakdown is not in this script. Limitation: untouched pages are shared between subgroup rows, so those rows are not independent.
- 2026-11-19 (T20, Abby): Ablation results are reported per set. Chosen over pooling the two sets row by row, which would double-count them. Limitation: AnyText and DiffSTE cells for these four versions are not independent evidence.
- 2026-11-19 (T20, Abby): The ablation adds rule B and AUC by importing the T11 functions in `shared/score.py` (`document_folds`, `crossfit_rule_b`, `auc`, `compute_metrics`, `resample_indices`); nothing is copied. Chosen over its own rule B copy. Limitation: with so few untouched pages per cell (49 or 100), cut-offs and ranges are rough.
- 2026-11-19 (T20, Abby): For the ablation, one page ID is one document (149 documents), so the 2-fold split and the 1,000-resample bootstrap (seed 42) treat each ID as one unit and take all of its rows together, which also keeps the 49 pages shared by AnyText and DiffSTE together. Chosen over resampling single rows, which would split a page from itself. Limitation: assumed from the page IDs, since the safe files have no document ID.
